# 8. Дисциплина измерений: чем прибор врёт и как это ловить

Семь уроков в `07_lessons.md` — про стратегию. Этот документ — про инструмент: три класса
ошибок, которые в этой кампании стоили дороже любой архитектуры, и правила, которые мы вывели
после того, как прибор три недели подряд говорил «нет».

Все числа — наши собственные измерения; артефакты перечислены в конце.

## 8.1 Метрика: платформа считает global, а не среднее по блокам

Полгода проект отбирал модели по per-block метрике — и это было ложное утверждение о метрике
платформы. Проверка по официальному baseline (прогон `baseline.onnx` на всём valid, 3.53 млн
scored-строк):

| статистика | значение |
|---|---|
| global weighted Pearson | **0.6170522890223754** |
| block (среднее по 1872 блокам) | 0.5895945115859251 |
| опубликовано организаторами | 0.617052 |

Совпадение с global до седьмого знака. Ранжирование при этом разное: модель `twenc_kd` по block
была лучше контроля на +0.003, по global — хуже на 0.036.

**Правило.** Отбор и слот-гейт — только по метрике платформы; вторая метрика остаётся
диагностикой дрейфа. Проверять метрику калибровкой по официальному baseline до первого отбора,
а не после.

## 8.2 Тихие ошибки: параметр, который влияет на лосс, обязан падать

Три случая одного класса за кампанию. Ни один не был виден в логах как ошибка.

**(а) Нулевые веса строк.** Флаг `--row-weight-col is_scored` брал колонку, которая истинна
только в валидной части. Веса train-строк стали нулевыми, корреляционный член лосса — константой,
`rho` в каждой строке лога — `+0.0000`.

| прогон | веса train-строк | tail120 global |
|---|---|---|
| три прогона с флагом без `--row-weight-hybrid` | 0 | 0.688593 — все три бит-в-бит |
| прогон без флага вовсе | 1.0 | **0.710646** |

Цена — **0.022 global**. Отдельно проверено: `p_hat` против единичных весов даёт +0.0002, то есть
работает не схема весов, а их ненулевость.

**(б) Знаковые веса.** Колонка `t0` знаковая; подстановка её в веса строк дала отрицательные веса
и разрушенное обучение: global **0.3183 / 0.3058** против 0.7128 у базовой модели.

**(в) Молчаливый экспорт.** LSTM-клетка экспортировалась как GRU: конфигурация «принята», модель
другая. Ось «LSTM» была закрыта по дефекту сборки, а не по измерению.

**Правило.** Любой параметр, влияющий на лосс (веса, маска, колонка, тип клетки), обязан
отказывать на бессмысленном входе: средний вес ноль, отрицательные веса, колонки нет в данных,
тип не поддержан экспортом. Деградация молча — запрещена. Четвёртый случай того же класса —
`--corr-mix`, измеренный на выключенном корреляционном члене: ось «не двигала счёт», потому что
двигать было нечего.

## 8.3 Чистота среза: «честная» валидация может быть на 85 % обучающей

Объединённый файл был устроен как `10607 train-групп + 1873 valid`. Отсюда:

| `--max-seq` | что попадает в обучение | valid, видимый моделью |
|---|---|---|
| 10607 | только train | никакой — чисто |
| 12360 | train + `g0..g1752` | 1753 группы из 1873 |

Срез `g800..g1872` («honest1073») для модели с `max_seq 12360` на **85 % лежит в обучении**.
Подпись загрязнения — знак разности `tail120 − honest`: у чистых моделей он положительный
(+0.0158 у записи, +0.0295 у одного из членов), у загрязнённой — **−0.0494** (0.760 против 0.711).
«Лучший в проекте» honest-счёт оказался памятью.

При этом одно условие ничего не решает: два члена, формально видевшие валид (тот же `max_seq`),
дали Δ +0.0217 и +0.0259 — 3.5 млн целей на 116k параметров за 8 эпох модель не запомнила.

**Правило.** Чистота — конъюнкция: `max_seq` выше границы train **и** диагностика
`Δ = tail − honest < +0.010`. Диагностика печатается каждым прогоном; прогон с плохим Δ
не попадает в сравнение.

## 8.4 Время: абсолютные µs/row не переносятся

- Один и тот же ансамбль стоил 23.97 µs/row на пустой машине и 35.10 под нагрузкой — 1.45×.
- Между двумя машинами якорь отличался в 2.4×; переносится только отношение к якорю.
- Линейность по числу графов держится на обеих машинах: **+8.8 µs/row на граф**.
- Замер, снятый при работающем в фоне скоринге, недействителен: 48.64 против честных 36.45.

**Правило.** Мерить на пустой машине; иначе — отношение к якорю в одном прогоне. Абсолютное число,
полученное под нагрузкой, выбрасывается, а не «поправляется на глаз».

## 8.5 Отбор: маргинально, по двум метрикам, с предрегистрацией

- **Маргинальный критерий, а не абсолютный.** Механизм принимается, если добавляет к текущему
  лучшему конвейеру. Дистилляция, слабая соло, в конвейере даёт +0.003.
- **Две метрики.** Кандидат берётся, только если block вырос **и** global не упал. Одна метрика
  обманывает: block слеп к дрейфу, global слеп к структуре.
- **`allrows` — не селектор.** Ансамбль, лучший по `allrows`, проигрывал официальной метрике на
  0.005 (0.5277 → 0.65475 против 0.65948).
- **Порог до числа.** `c11` объявлялся живым при ≥ 0.66028 (засчитан: +0.00090); тяжёлая доза —
  при 0.66093…0.66173 (не попала: 0.65893, механизм закрыт). Порог, придуманный после результата,
  — не критерий.
- **Доза переносится хуже, чем знак.** Локальная доза монотонна (+0.00316 → +0.00378 → +0.00480),
  платформенная насыщается (+0.00090 → … → −0.00145). Отношение переноса на первой точке ≈ 25 %.

## 8.6 Отрицательный контроль

Каждый прибор проходит негатив до первого использования: калибровка по официальному baseline
(global 0.617052), placebo-null из 1000 перемешиваний меток, парная swap-нулевая. Журнал вердиктов
10.11 на 18 парах: **18/18 DEAD, после BH-FDR значимы 0** — то есть одиночные модели и
перестановки равных членов прибор не различает. Это диагноз классу гипотез, а не приглашение
мерить точнее.

**Правило.** Прибор без негативного контроля не допускается к отбору; прибор, который три недели
говорит «нет», меняет класс гипотез, а не настройки.
