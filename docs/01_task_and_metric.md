# 1. Задача, контракт и метрика

## 1.1 Постановка

Соревнование Wunder Fund «Alfa Connectome» (сентябрь–ноябрь 2026). Данные — поток стакана и
сделок по двум инструментам, `i0` и `i1`, по 112 признаков на строку, нарезанный на
последовательности по 20 000 строк. Первые 99 строк — прогрев. На каждой следующей строке
модель обязана выдать два числа, `t0` и `t1`, — «индикаторы будущего движения цены» первого
инструмента. Состояние сбрасывается между последовательностями, то есть модель обязана быть
причинной и потоковой.

| | |
|---|---|
| train | 10 607 последовательностей |
| validation | 1 873, с известной маской заскоренных строк |
| public test | ~1 970, отдаётся построчно |
| всего строк на инференсе | 39.4 млн |
| бюджет времени | 60 минут (жёсткий таймаут платформы 4200 с) |
| бюджет размера | ZIP ≤ 20 МБ, ONNX Runtime, CPU, 1 поток, без сети |

39.4 млн строк на одном ядре за 60 минут — это около **91 µs на строку** на всё, включая
переиспользование состояния и Python-колбэк платформы. Это ограничение оказалось не
технической деталью, а фактором, определяющим класс решения: сколько членов ансамбля можно
себе позволить, зависит только от стоимости строки.

## 1.2 Метрика и три её ловушки

Метрика — взвешенный коэффициент Пирсона, считаемый **отдельно по каждому таргету** и затем
усредняемый, с клипом обоих рядов в ±2, весами `w = |clip(y, ±2)|`, по скрытой маске
заскоренных строк, пул по всем последовательностям.

Ловушка первая: **веса — это |y|**. Строки с малым движением почти не влияют на счёт, строки с
большим — определяют его. Любая ошибка масштаба на «крупных» строках стоит дороже, чем средняя
ошибка по всем.

Ловушка вторая: **клип ±2**. Предсказание за пределами клипа не улучшает и не ухудшает
корреляцию, но переобучение «в клип» (когда модель выдаёт большие значения там, где уверена)
начинает работать против неё. У команды, занявшей 94-е место, исправление масштаба базовой
модели организаторов (умножение на 0.25 без переобучения) дало +0.0568 — 83 % всего её
прироста. Это самый крупный одиночный рычаг, который мы видели в этой задаче.

Ловушка третья: **усреднение по таргетам при разных распределениях**. Мы измерили на 12
последовательностях: `E|clip(t1)| = 0.688` против `0.843` у `t0`, и 28.8 % строк `t1` вообще
не несут веса против 21.4 % у `t0`. Значит вес-лосс, оптимизируемый «как есть», перекашивается
в сторону `t0`, хотя метрика даёт обоим таргетам равную долю. Мы лечили это нормировкой
вклада таргетов в MSE-часть лосса.

## 1.3 Контракт сабмита

Пакет — ZIP до 20 МБ, внутри `class PredictionModel` с методом `predict(DataPoint)`. Состояние
можно держать в атрибутах модели, сбрасывая его по `seq_ix`. Платформа исполняет пакет в
одном потоке CPU без сети. Мы возили ONNX Runtime и четыре файла рантайма (графы + скейлер),
итоговый ZIP записи — 1.3 МБ против лимита 20.

Из этого контракта следует важное: **время — валюта**. Наши 26 µs/строка на ONNX давали три
члена ансамбля в 59 минут, то есть впритык. Быстрый численный рантайм (numpy-фьюз, затем C)
освобождал десятки минут — и это оказалось одним из главных упущенных рычагов (см.
`03_our_pipeline.md`, раздел про рантайм).
